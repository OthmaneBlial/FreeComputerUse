THREE WAYS TO WORK

Let it explore.
Or show it once.

Start with a goal and a model. When a task repeats, save it as a procedure with named values, so later runs replay locally and cost nothing.

01 / AUTONOMOUS

Give it a goal

It reads the page structure, asks your model for a small batch of typed actions, runs them and checks the result. Screenshots are an opt-in fallback.

02 / TEACH ME

Show or write the steps

Record what you do in the browser, write the steps in English or French, or keep a run the model completed. Passwords and files become values, never stored.

03 / SMART REPLAY

Replay, repair one step

Saved alternatives are tried first. If a button was renamed, the model repairs that step only, and the fix is saved as a new version.

04 / WHEN STUCK

It asks you to show it

A step that still fails can pause the run. Do it yourself in the live browser and resume: your action is saved with the next version.

↳ Requests in other words or another language find the right procedure and fill in its values. How teaching works.

THE FLAGSHIP PROCEDURE

A Google Play release.
Without surprises.

Upload a bundle, add the release notes and send the release for review. The steps work on the English and French console, and every run stops for you where it matters.

  • You sign inIt never types your Google password, never answers 2-Step Verification and never solves a CAPTCHA. On a sign-in page it pauses for you.
  • You approve the submissionSave and publish and Send changes for review ask every time, with the release summary in the prompt. A recording is never a standing approval.
  • "In review" is not "published"The run reports what the console says. Google still reviews the release.
  • Several accounts, blocking errorsA value can pick the developer account. When the console refuses a submission, the run fails and quotes the console's message.

SAFETY YOU CAN SEE

The browser stays yours.

Execution, browser profiles, history and downloads stay on your machine. The goal and the page context needed to plan go to the provider you chose. The model cannot run shell commands or arbitrary JavaScript.

  • Approve each new website
  • Confirm sensitive steps on every run
  • No CAPTCHA solving, no 2-Step Verification bypass
  • Keys in the Keychain; secret values never saved in procedures or exports
  • Screenshots only with FCU_VISION=1, form fields masked

Sensitive-step detection relies on heuristics and cannot recognise every deceptive page. Local data is not encrypted and does not expire on its own. Normal mode blocks private and reserved network addresses unless you approve them; ultra mode is opt-in and skips those checks. Read the security boundaries and local data before using personal data.

COMMON QUESTIONS

Know the limits.
Keep control.

Short, evidence-based answers before you connect an account or open a site.

Are procedures in the npm package?

Not yet. The npm release 0.2.23 predates procedures, teach mode and smart replay. They are on main: run from source until the next release.

Will it publish my app to Google Play by itself?

No. You sign in, and Save and publish and Send changes for review ask you on every run. The procedure ends when the release is in review, which is not published. On the real console, only the signed-out start has been checked so far.

Which models have live evidence?

DeepSeek Flash (API), Claude Opus 5.5 through Claude Code, and gpt-6.1-sol through Codex CLI each completed the nine-run procedure benchmark. The Claude and OpenAI API routes have contract tests only. See the dated support matrix.

What has been verified, and on what?

The full local gate (TypeScript, 221 tests, build, credential scan, dependency audit) passed on 25 October 2026 on macOS 26.6 with Node 25.9.0 and Chrome 155. Windows, Linux and other browser builds are unverified, and no result predicts success on arbitrary websites.
