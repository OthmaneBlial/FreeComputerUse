# FreeComputerUse 0.2.14

This release makes browser actions safer to target and keeps agent state and
token accounting reliable when a task or provider returns an edge case.

## What changed

- Profile filling is limited to one uniquely matched form. Ambiguous targets
  fail safely instead of touching another form.
- Risk checks consider visible control text alongside accessible labels, so an
  `aria-label` cannot conceal destructive wording shown to the user.
- A learned workflow is not replayed when its completion checks already pass.
- The agent remains reusable if trace persistence fails, and a failed approval
  listener cannot leave the pending confirmation queue stuck.
- Provider output above the reserved token limit is rejected. Cached input-token
  counts must be valid and no greater than total input usage.

## Install

Requires Node.js 22.13+, npm, and an installed browser.

```bash
npm install --global free-computer-use@0.2.14
FCU_BROWSER_CHANNEL=chrome agent doctor
FCU_BROWSER_CHANNEL=chrome agent ui
```

Open `http://127.0.0.1:4318`. Common page-reading and link-extraction tasks work
without a model key; open-ended tasks need a configured provider. See the
[README](https://github.com/OthmaneBlial/FreeComputerUse#quick-start) and
[support matrix](https://github.com/OthmaneBlial/FreeComputerUse/blob/main/docs/SUPPORT_MATRIX.md).
