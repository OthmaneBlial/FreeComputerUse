# FreeComputerUse 0.2.13

This release tightens how sensitive forms are handled and makes form-submission
checks match the request the browser actually sends.

## What changed

- Password, payment and one-time-code fields can be recognized from common
  labels and hints. Entry asks for human approval, then checks that the page and
  target did not change while approval was pending.
- Record extraction masks sensitive form values across inputs, textareas and
  selects. Accessibility snapshots keep labels and roles while omitting live
  editable values.
- Image submit controls are treated as form submissions and require approval.
- Submission verification follows a clicked submitter's `formaction` and
  `formmethod`, including the default submit button activated by Enter.
- Text extraction searches the source before applying its result limit.
- Streamed model output is bounded, and lookups for learned workflows and run
  history use indexes.

## Install

Requires Node.js 22.13+, npm and an installed browser.

```bash
npm install --global free-computer-use@0.2.13
FCU_BROWSER_CHANNEL=chrome agent doctor
FCU_BROWSER_CHANNEL=chrome agent ui
```

Open `http://127.0.0.1:4318`. Common page-reading and link-extraction tasks
work without a model key; open-ended tasks need a configured provider. See the
[README](https://github.com/OthmaneBlial/FreeComputerUse#quick-start) and
[support matrix](https://github.com/OthmaneBlial/FreeComputerUse/blob/main/docs/SUPPORT_MATRIX.md).
